How RENTX Works

Architecture transparency — what's real, simulated, and planned

FeatureImplementationStatus
SHA-256 Item PassportReal cryptographic hash chain in SQLite. Photo + serial + title hashed. Append-only with tamper detection.Built
Escrow Deposit SystemFull state machine: pending → held → released/disputed → resolved. Enforced server-side.Built
Multi-Dimensional ReputationRenter: punctuality, item care, disputes. Owner: reliability, response time. Computed from rental history.Built
Need-Based MatchingNLP keyword matching to curated equipment bundles. Returns best available items per tag.Built
User AuthenticationDemo: simulated Google SSO + OTP phone auth. Production would use Firebase Auth / OAuth 2.0.Simulated
Payment ProcessingDeposit amounts tracked numerically. Real payments would integrate Stripe or payment gateway.Simulated
Push NotificationsToast notifications in-app only. Production would add email/SMS via SendGrid or Twilio.Simulated
Blockchain IdentitySHA-256 hash chain provides tamper evidence. Full blockchain would add decentralized consensus.Vision
AI Damage AssessmentManual owner rating. Vision: computer vision model for automated condition grading from photos.Vision
Community ModeDatabase column exists. Full feature would add free borrowing, karma points, lending circles.Vision
Demo Authentication: This app uses simulated sign-in (Google prompt + hardcoded OTP "123456") and X-User-Id header-based sessions for demo purposes. In production, real OAuth 2.0 and session tokens would be used.
